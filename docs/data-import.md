# 数据导入与备份

## Excel 导入

页面或 `GET /api/import/positions` 可以下载模板。工作表名称必须是 `fund_position_import`，支持以下列：

| 列名 | 必填 | 说明 |
| --- | --- | --- |
| `基金代码` | 是 | 基金代码 |
| `基金名称` | 是 | 导入时用于创建基金资料 |
| `买入日期` | 是 | `YYYY-MM-DD`；也支持 Excel 日期值 |
| `买入金额` | 是 | 正数 |
| `买入净值` | 是 | 买入时确认的单位净值 |
| `买入份额` | 是 | 买入时确认的份额 |
| `申购费用` | 否 | 非负数，缺省为 `0` |

单次最多导入 1000 行，文件大小不能超过 5 MB。导入过程中如果任意一行校验失败，整批事务回滚，不会留下部分持仓。

## JSON 导入

```json
{
  "version": "1.0",
  "positions": [
    {
      "fundCode": "001513",
      "fundName": "示例基金A",
      "purchaseDate": "2026-07-01",
      "purchaseAmount": "20000.00",
      "confirmedNav": "3.2100",
      "confirmedShares": "6230.5296",
      "purchaseFee": "0"
    }
  ]
}
```

金融数值必须使用字符串。截图识别结果如果缺少必填字段，应先人工核对，不要让识别模型猜测。

## 备份与恢复

- `GET /api/backup` 导出账户、基金、净值、盘中估算、持仓、交易、快照、信号、策略状态、复盘和操作日志。
- 恢复会清空当前业务表后整体写入备份内容；这是破坏性操作，执行前必须保存当前备份。
- 备份文件包含个人投资数据，不应提交 Git 或上传到公开 issue。
- 推荐定期保留多个带日期的离线备份，并实际演练一次恢复流程。

## 数据库迁移

迁移文件在 `drizzle/` 中按顺序提交。应用启动和 `npm run db:migrate` 都会调用 `ensureDatabase()` 执行未完成迁移。修改 schema 后先生成迁移、运行测试，再在干净数据库上验证启动。
